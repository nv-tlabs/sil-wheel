Clip List Search Help:

Filter search results to a specific set of clip IDs. Your file must be a .json file containing a JSON array of strings: 

            ["clip_id_1", "clip_id_2", "clip_id_3"]

... or a JSON object with a clip_ids key: 

            {"clip_ids": ["clip_id_1", "clip_id_2", ...]}

The list is stored once on the server under a content-addressed hash. Re-uploading the same content returns the same hash, so the URL stays small regardless of list size and the filter is shareable across users.

Trajectory Search Help:

The trajectory search consists of writing a valid python expression that evaluates to True or False for each video. You have the following variables available to use:

  1. speed: A numpy array with the instantaneous speed per video frame in meters per second
  2. speed_kph: The same as speed but in kph
  3. acceleration: A numpy array with the instantaneous acceleration per video frame in m/s^2
  4. curvature: A numpy array with the instantaneous 2D (on x-y) curvature per video frame in m^-1
  5. jerk: A numpy array with the instantaneous jerk (derivative of acceleration) per video frame in m/s^3

In addition you also have the following functions/objects:

  1. mean: Maps to np.mean
  2. sum: Maps to np.sum
  3. min: Maps to np.min
  4. max: Maps to np.max
  5. all: Maps to np.all
  6. any: Maps to np.any
  7. logical_and, logical_or: Maps to np.logical_and / np.logical_or
  8. len: Maps to len

Example searches:

  1. mean(speed_kph) > 10: The average speed of the vehicle is more than 10 km/h
  2. any(speed == 0) and any(speed > 10): The vehicle is both stopped and moving in the video
  3. sum(curvature > 0.1) > 10: The video has more than 10 frames with curvature larger than 0.1
  4. sum(logical_and(speed_kph > 20, curvature > 0.1)) > 10: The video has more than 10 frames where the speed is simultaneously more than 20 km/h and the curvature larger than 0.1
  5. sum(speed < 0.5) > 150: Prolonged Stop

Trajectory-to-Trajectory Search Help:

Trajectory-to-Trajectory Search retrieves clips whose ego trajectory shape is similar to a given clip. Paste a clip ID; the system extracts that clip's trajectory shape and ranks all other clips by similarity. Useful for finding more clips with the same maneuver — e.g. a sharp lane change, a long stop, or an arcing turn.

Range: the dual slider (default 0–20 s) selects a sub-segment of the source clip's trajectory to use as the query. The window's duration also picks the retrieval granularity:

  • ≤ 6 s → short-shape index — best for brief maneuvers (e.g. a single lane change)
  • ≤ 15 s → medium-shape index
  • > 15 s (default) → full-trajectory index

Caption Substring Search Help:

Caption Substring Search enables you to find specific words or phrases within video captions. For each video, the search returns True if the specified term or pattern is found, and False otherwise. When a match is found, the corresponding word or pattern is highlighted in yellow within the caption for easy identification.

The following query forms are supported:

  • Single terms: A bare word like crosswalk matches clips whose captions contain that exact token.
  • Quoted phrases: Wrapping terms in double quotes, e.g. "heavy rain", matches clips whose captions contain that exact phrase in that order.
  • Unquoted multi-word input: Consecutive unquoted words are automatically treated as a quoted phrase — heavy rain is equivalent to "heavy rain". Hyphens are replaced with spaces before this step, so stop-sign is treated as "stop sign".
  • Boolean operators: AND, OR, and NOT are supported. For example, crosswalk AND rain returns clips whose captions mention both, while rain NOT highway excludes clips that mention highways.

Rewrite: Click the Rewrite button to expand your query into related variants using an LLM (e.g., "nudge" → "swerve", "lateral shift", "veering"). Results from all variants are combined to improve recall. Uncheck any tag to exclude it from the search.

Caption Semantic Search Help:

Caption Semantic Search retrieves clips whose captions are semantically similar to your query. The query is encoded with the same model used to embed the captions, and the closest matches are ranked by cosine similarity. Unlike keyword-based caption substring search, this finds clips by meaning even when the exact words are not present in the captions.

Rewrite: Click the Rewrite button to generate semantically related query variants via an LLM. Results from all variants are union-ed, keeping the highest similarity score per clip.

Text-to-Video Search Help:

Text-to-Video Search allows users to retrieve relevant video clips by entering free-form text queries (e.g., "highway driving" or "pedestrian crossing"). The system uses text-to-video embedding similarity to match the query against precomputed video representations, enabling intuitive and flexible search based on meaning rather than exact keywords. This functionality supports both descriptive phrases and single-word prompts.

Rewrite: Click the Rewrite button to generate semantically related query variants via an LLM. Results from all variants are union-ed, keeping the highest similarity score per clip.

Video-to-Video Search Help:

Video-to-Video Search retrieves clips that are visually and semantically similar to a given clip. Paste a clip ID; the system encodes that clip with the same Cosmos-Embed-1 model used by Text-to-Video Search and ranks all other clips by cosine similarity against it. Useful for finding more clips like one that already caught your eye.

Image-to-Video Search Help:

Upload an image to search for visually similar video clips. The image is encoded with a SigLIP image encoder and matched by cosine similarity against precomputed embeddings of sampled video frames and Florence2-detected regions. Each clip's score is the highest similarity across all of its frames and regions. The uploaded image is stored for the current session and reused until a new image is uploaded or the search is cleared.

Text-to-Image Search Help:

Text-to-Image Search retrieves video clips from free-form text queries using SigLIP, an image-text contrastive model. Each clip is represented by SigLIP embeddings of sampled frames and regions detected by Florence2; the query text is encoded into the same embedding space and matched by cosine similarity. The highest similarity across all frames and regions of a clip is kept as that clip's score, enabling semantic search grounded in visual content even when exact keywords or labels are missing.

Rewrite: Click the Rewrite button to generate visually related query variants via an LLM (e.g., "school zone sign" → "speed limit sign", "crosswalk ahead sign", "children crossing sign"). Results from all variants are union-ed, keeping the highest similarity score per clip.

Perception-based Search Help:

Perception-based Search allows you to find video clips based on in-car perception and spatial relationships to the ego vehicle of a particular object class. Select the object class from the dropdown menu and then choose a search type.

Search Types:

  1. By Count: Find clips containing at least N instances of a specific object type
  2. By Range Query: Find clips with objects in specific directions relative to the ego vehicle, within a certain distance, for a minimum duration

Direction Selector:

The circular diagram shows 6 regions around the ego vehicle. Click on sections to select/deselect directions where objects should be detected.

Top Clusters For:

The query is encoded with the same model the run was clustered on (Cosmos / Caption / Visual, per the run's Embeddings setting), then ranked against each cluster's centroid, not against individual clip embeddings as the other text searches do. That's what makes this a cluster-level search rather than a clip-level one.

Clustering Tools Help:

K-Means on the current search results. Runs in the background; the run list refreshes on completion.

Configuring a run

  • Clusters: Number of K-Means clusters. UI runs are capped at 20 000 clusters / 5 000 000 input clips. For bigger sets, cluster offline via examples/cluster_from_search.py and upload.
  • Spherical K-Means: Normalise vectors first (cosine similarity).
  • Max pts/centroid: FAISS training cap — at most clusters × this points. Higher = better quality, slower (default 256).

Browsing a run

Click View Selected Run. Each clip card shows Show Cluster N (d=…) — small d = central, large = outlier. Drill into a cluster by clicking a UMAP centroid, clicking Show Cluster N on a card, or using Top clusters for: below.

Top clusters for…

Returns clusters ranked by L2 distance from your query to each centroid (encoded with the run's embedding model). Different from caption/semantic/visual search, which return clips. Rows show cluster size + topic keywords; click to drill in.

Delete Run removes a run entirely. Older runs without persisted centroids return empty for Top clusters for….

Classifier Tools Help:

Use this to run a previously trained binary classifier on a specific label. Select the embedding type that matches the one used during training. Whenever a classifier is trained and ready to use the Use Classifier button should be enabled.

Embeddings: Select the embedding type that matches the classifier you want to use. Text-to-Video uses Cosmos-Embed-1; Caption uses Qwen3-Embedding-8B; Visual uses Florence2 SigCLIP.

Probability Threshold: Filter clips by predicted score using > (most confident positives) or < (most confident negatives) and a value between 0 and 1. Click Use Classifier to apply.

Export Classifier: Downloads the trained classifier weights as a .pkl file containing a logistic regression model. You can apply it offline by computing embeddings for new clips and calling model.predict_proba(embeddings).
